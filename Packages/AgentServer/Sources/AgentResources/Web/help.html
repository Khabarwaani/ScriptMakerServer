Streaming and output contract

POST /execute returns one final validated JSON value or a structured error by default. The optional status query parameter defaults to false and can be omitted. Add ?status=true for status/progress SSE updates plus one validated result or terminal error. Raw provider text is not returned in either mode. In Try it, tick Show status updates to opt in. The X-Execution-ID header identifies the execution. In final-only mode it arrives with the final response; in status mode the header and first event arrive when work is accepted. Every event carries JSON data and preserves ordering within that execution.

Heartbeats and progress

Status events carry lifecycle state, a periodic heartbeat or provider progress. A heartbeat shows that work is tracked; it does not prove model progress. Keep these events separate from provider text.

Provider output and final result

Provider text stays internal. Final-only mode returns the validated JSON directly. In status mode, one result event contains final JSON that passed the selected version's output schema; completed follows it.

Invalid final JSON and schema mismatches return a structured error in final-only mode, or a failed event followed by stream closure in status mode. They never emit successful completion. Known Antigravity tool transport annotations are separated from the result; arbitrary extra fields still fail strict schemas.

Closing the HTTP connection leaves execution running. Monitor it with GET /status or explicitly cancel it. Streams are not resumable in this version. Status polling clients can use a five-second interval.

Provider worker pool and latency

The server creates workers lazily and retains up to provider_pool_size (default 5) globally across agents and providers. Healthy workers have no idle expiry. A compatible idle worker is reused; otherwise the least recently used idle worker may be replaced. Busy workers are protected. Temporary burst workers obey max_processes and memory limits and are removed after finishing.

Each request gets a fresh native context and schema. Codex request threads are deleted and unloaded after use; Grok sessions are closed. Antigravity uses fresh processes because a safe reset protocol is unverified. Grok with explicit model/effort overrides also stays fresh until configuration parity is verified. Unsupported reset or reset failure disables reuse for that provider for this server session; failed work is never replayed.

Execution failures, timeouts, cancellation and reset failures retire the affected worker. Normal shutdown closes all owned workers. After a crash or forced kill, workers can survive until the next restart; the server verifies PID, birth time, executable and ownership before cleanup. Unverified processes are preserved. There is no separate supervisor.

GET /status includes worker_pool counts and memory, provider worker_reuse modes, and per-request phase_timings, queue_reasons and worker_reused. Readiness/preparation time precedes acceptance; queue time is separate from running duration. Phase timings distinguish startup, generation, validation and cleanup; total time begins at execution-manager entry. Open Execution logs to inspect these bounded diagnostics.

Session execution logs

View execution logs Download full log

The log viewer lists execution ID, time accepted and status. Open View details for state history, duration and error code/message. The viewer reads the latest 200 state entries; the download contains the full session log.

Accepted executions are recorded in a temporary JSONL file through queued, running, cancelling and completed/failed/cancelled states. No prompts, results, credentials or raw provider output are logged. Records rejected before acceptance have no execution ID and return their error directly. In-memory tracking is purged on shutdown; the log file is cleared on a fresh server start. The startup console prints its temporary path.

Execution start time and duration

Tracked executions belong only to the current server session. The server purges them after shutdown finishes; a new server starts with an empty list. Completed, failed and cancelled records keep the execution ID, state and timing fields to save memory. Records also keep bounded phase timings, queue reasons and a worker reuse flag. Failed records keep an error code and message so Tracked executions explains the failure. Agent/provider metadata and execution handles are released; prompts and results are not retained in tracking records. Closing a browser page does not stop the server or cancel its work.

started_at is the ISO 8601 acceptance time. running_at is the time work begins running and is absent while queued or if cancelled before running. elapsed_seconds is running duration, excluding queue time: zero before running, increasing while running or cancelling, and fixed at ended_at once completed, failed or cancelled.

GET /status and SSE events include this timing metadata. The execution page and Try execution page display start time and duration, with active durations updating every second. GET /status in Try it returns the same fields as JSON.

Agent-specific input and output formats

Contracts and documentation are loaded from /openapi.json. GET /agents returns only agent IDs, names and available versions. Select a version to inspect its exact role, instructions and schemas. Try it builds input controls from that schema, including enum choices and optional fields, while keeping a separate editable request JSON box. Connection errors show the HTTP method and path.

Structured errors and HTTP behavior

Errors before streaming use HTTP status codes and a JSON error envelope. After streaming starts, errors use an SSE failed event. The envelope contains code, message and execution_id when assigned. Invalid agent input includes details.violations listing each missing or invalid field, its JSON Pointer path, failed constraint, expected requirement and actual type. Missing optional fields are allowed; missing fields with defaults are filled before validation. No credential or private provider configuration is returned.
