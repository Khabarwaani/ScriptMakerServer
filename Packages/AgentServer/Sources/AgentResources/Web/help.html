01 · Start, restart and graceful shutdown

Open AgentServer.xcworkspace, choose AgentServer → My Mac, and press ⌘R. The default address is http://127.0.0.1:8080/.

swift build --package-path Packages/AgentServer
swift test --package-path Packages/AgentServer
swift run --package-path Packages/AgentServer AgentServer

# Graceful stop, in another terminal:
swift run --package-path Packages/AgentServer AgentServer stop

In Xcode, run the AgentServer-Stop scheme for graceful shutdown. Xcode's debugger Stop button may terminate abruptly. Starting again gracefully stops the previous managed AgentServer on that port before binding the replacement; unrelated port owners are not stopped.

Shutdown allows accepted work to drain for up to 15 minutes. It finishes sooner when work completes. After the grace period, remaining work is cancelled and processes are reaped. New executions are rejected while draining.

The server reads config, agent definitions and pages from build output. Provider execution directories default to macOS Application Support, reducing access to the source folder in Documents.

02 · Providers and existing CLI logins
Provider IDCLIExecution and output
codexCodexNon-interactive exec, JSONL events, native schema and final-message file.
antigravityAntigravity / agyHeadless stream-json, step updates, text deltas and structured final output.
grokGrok Build CLIHeadless prompt file and streaming message events; final JSON is validated by the server.

Adapters inherit the normal user environment and reuse the CLIs' cached credentials. There is no separate server login, credential store or remote model-list prerequisite. Codex checks cached login status; Antigravity and Grok check local CLI initialization and let execution validate backend authentication.

Configure executable paths and optional model IDs in config/server.json. Without a model setting, each CLI uses its configured default. If Xcode cannot find a CLI on PATH, configure its absolute executable path. Provider-specific sandbox and permission checks remain enabled.

03 · Read the execution view: heartbeat, output and final result

Heartbeat and status

Lifecycle states and periodic heartbeats show that the server still tracks the execution. They are separate from provider output. A heartbeat is emitted about every 10 seconds while work is queued, running or cancelling.

A heartbeat alone does not prove model progress. Provider step updates are displayed as progress when the CLI exposes them.

Provider output

Incremental provider text appears as soon as a supported event arrives. This text is provisional: it may contain commentary or candidate JSON and can still lead to failure.

Providers may buffer text, perform tools or think silently before producing a response.

Validated result

Only the final provider result is parsed and validated against the resolved agent version's output schema. On success, the result appears as formatted JSON and the execution becomes completed. Antigravity's structured_output is used when available, separately from its response text.

Failure and cancellation

Invalid JSON or a schema mismatch produces failed; no successful result is displayed. A response containing extra fields such as toolAction or toolSummary fails an output schema with additionalProperties: false. Provider metadata belongs to its transport envelope, not the agent result.

Click Cancel this execution to stop that execution. The page reports cancelling until process termination is confirmed. Closing the page detaches its stream and leaves execution running; status still tracks it.

Expand Request and raw events on the run page to inspect the HTTP/SSE data. The tracked-execution list refreshes every three seconds.

05 · HTTP endpoints and JSON request schema
Method and pathPurpose
GET /agentsValid agent IDs, versions, latest stable, public contracts and configured providers.
POST /executeAccept JSON input and stream SSE events.
GET /statusHealth, uptime, active/queued counts, process memory and retained execution records.
POST /executions/{id}/cancelCancel one execution safely; repeated requests return its current state.

Execution request

{
  "type": "object",
  "required": ["agent_id", "provider", "input"],
  "properties": {
    "agent_id": {"type": "string", "description": "Registered agent ID"},
    "version": {"type": "string", "description": "Optional exact semantic version"},
    "provider": {"enum": ["codex", "antigravity", "grok"]},
    "input": {"type": "object", "description": "Agent-specific JSON input"}
  }
}

Omit version to choose the highest stable SemVer; prereleases must be selected explicitly. The resolved version remains fixed for the execution.

curl -N -X POST http://127.0.0.1:8080/execute \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{"agent_id":"JSONEcho","provider":"codex","input":{"text":"hello"}}'

curl http://127.0.0.1:8080/status

06 · SSE events and response formats

The response content type is text/event-stream. Obtain the execution ID from X-Execution-ID, the first event, or status records. Every event has a JSON payload and preserves per-execution ordering.

EventPayload
startedexecution_id, agent_id, resolved version, provider, status
statusexecution_id, status; optional progress object
outputexecution_id, incremental text
resultexecution_id, schema-validated result
completedexecution_id, terminal status
failedexecution_id, structured error
cancelledexecution_id, confirmed terminal status
event: status
 data: {"execution_id":"exec_001","status":"running"}

 event: output
 data: {"execution_id":"exec_001","text":"partial text"}

 event: result
 data: {"execution_id":"exec_001","result":{"result":"hello"}}

 event: completed
 data: {"execution_id":"exec_001","status":"completed"}

Whitespace before event/data is omitted in actual SSE responses. Heartbeats do not replace output. A result event is emitted only after validation; successful completion follows it. Streams cannot be resumed in Version 1.

Status snapshot

{"status":"healthy","server":{"version":"1.0.0","uptime_seconds":120},"active_executions":1,"queued_executions":0,"executions":[{"execution_id":"exec_001","agent_id":"JSONEcho","version":"1.0.0","provider":"codex","status":"running","streaming":true,"started_at":"2026-10-12T06:00:00Z"}]}

Structured errors

{"error":{"code":"output_schema_validation_failed","message":"The final result does not match the agent output schema.","execution_id":"exec_001"}}

Before streaming, errors use HTTP status codes. After streaming begins, failures use the failed event. Error categories cover invalid requests, unknown agents/versions/executions, invalid definitions, unavailable providers, initialization and launch failures, timeouts, invalid final JSON, validation failures and cancellation failures. Client errors do not contain credentials or private provider configuration.

07 · Central configuration and resource budgets

Edit Packages/AgentServer/config/server.json and rebuild to refresh the packaged defaults. To use an external file, set AGENT_SERVER_CONFIG to its absolute path before starting.

host / port127.0.0.1 / 8080Loopback HTTP binding.

shutdown_timeout_seconds90015-minute graceful shutdown allowance.
execution_timeout_seconds1800Maximum running execution duration.

Environment overrides: AGENT_SERVER_PORT and AGENT_SERVER_AGENTS_DIR. There is no fixed five-process limit. Process memory is monitored; work can be deferred under pressure. The server does not buffer unlimited events, output or status records.

08 · Create, version and check a Swift agent package
swift run --package-path Packages/AgentServer AgentTools add MyAgent 1.0.0
swift run --package-path Packages/AgentServer AgentTools check
swift run --package-path Packages/AgentServer AgentTools check --build
swift run --package-path Packages/AgentServer AgentTools version MyAgent 1.1.0 1.0.0

Each package contains a manifest, README, Swift source, tests and semantic version directories with role.md, instructions.md, optional input.schema.json and required output.schema.json. Published versions are immutable. Swift packages embed resources at build time; runtime Markdown discovery is separate.

Supported schema assertions include types, properties, required fields, additionalProperties, items/prefixItems, array uniqueness and size, string length/pattern, numeric bounds/multipleOf, enum/const, local references, allOf/anyOf/oneOf/not and if/then/else. Unsupported assertions such as format and unevaluatedProperties make definitions unavailable rather than being silently ignored.

Use JSONEcho for a small end-to-end provider check before running research. For a real agent, write explicit workflow instructions and precise schemas, and avoid credentials or private configuration in definitions.
